# Checklist for a technical page

Answer each question with yes or no. Fix each "no" before you report the page
as done.

## Words

- Does each thing have one name, the same in every sentence and in
  `GLOSSARY.md`? If the glossary has no entry, does the page use one word for
  it throughout?
- Does each word have one meaning on the page?
- Is each word the simplest one that is correct ("use", "start", "help",
  "about", "show")?
- Is the page free of idioms, metaphors, slang, humour and filler?

## Sentences

A label with a colon ("`web/`: the single-page app") is not a sentence. Every
full sentence counts, also in a list or a table.

- Does each instruction have 20 words or fewer?
- Does each descriptive sentence have 25 words or fewer?
- Does each sentence hold one instruction or one topic?
- Is each sentence in the active voice, unless the agent is unknown or not
  important?
- Is each verb in a simple tense, with no "-ing" form as the verb?
- Is each instruction in the imperative?
- Are "the", "a", "is" and "are" present where English needs them?

## Structure

- Does each paragraph have one topic and six sentences or fewer?
- Does the page give the result first, then the details?
- Does each condition come before its instruction?
- Does each warning come before the step that it applies to?
- Are the steps a numbered list and the parallel items a bulleted list?
- Is each line of argument in prose, not in a list?

## House style

- Is the spelling British with the Oxford "-ize" ("behaviour", "organize")?
- Is the page free of the serial comma?
- Are the headings in sentence case?
- Is the page in the present tense, with no history of the change?
- Is the page free of tracker IDs and phase numbers?
- Is the page free of plans, studies and decision records?
- Are paths, commands and code names in backticks?

## Truth

- Does each path exist from the base that the page states, or else from the
  repository root?
- Does each link open, and does each linked heading exist?
- Did each safe command run with the result that the page states?
- Does the page say nothing that another doc already says? If it does, is it
  a link instead? `AGENTS.md` may repeat the commands that agents run most.
